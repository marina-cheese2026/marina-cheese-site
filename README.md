## Git и публикация — автодеплой на Beget через GitHub Actions

Выбрали этот способ как самый безопасный и правильный: без Vercel как посредника (хостинг и домен уже оплачены на Beget), без ручной заливки по FTP каждый раз, и без того, чтобы пароль от хостинга где-либо мелькал в переписке — вы вводите его один раз сами, в защищённое хранилище GitHub.

Локальный git-репозиторий уже создан (`git init`, коммиты сделаны). Файл `.github/workflows/deploy.yml` уже готов: при каждом пуше в ветку `master` сайт сам заливается на Beget.

### Что нужно сделать один раз (только вы, руками — эти шаги требуют входа в ваши аккаунты)

1. **Создать репозиторий на github.com** — New repository, пустой (без README/gitignore, они уже есть локально).
2. **Прислать мне ссылку на репозиторий** — я запушу код (`git remote add origin ... && git push -u origin master`), это не секретные данные.
3. **Узнать в панели Beget** (Файловый менеджер / FTP-доступ) три значения:
   - хост FTP-сервера (например `ftp.beget.com` или адрес, который покажет панель),
   - логин FTP,
   - пароль FTP,
   - путь до папки сайта на хостинге (server-dir, например `/site/public_html` или домен-папка).
4. **Внести их в GitHub** сами: репозиторий → Settings → Secrets and variables → Actions → New repository secret. Создать четыре секрета:
   - `FTP_SERVER`
   - `FTP_USERNAME`
   - `FTP_PASSWORD`
   - `FTP_SERVER_DIR` (путь до папки сайта, со слэшем в конце, например `/public_html/`)

   Пароль при этом виден только GitHub и никогда не попадает ко мне и в чат.
5. После этого — любой пуш в `master` (в том числе мой, когда я правлю сайт) сам обновит сайт на вашем домене на Beget. Первый запуск можно увидеть во вкладке **Actions** репозитория.
